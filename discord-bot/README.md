# Discord-бот статистики 5thMR

Discord-бот работает совместно с основным сервисом `5thMRsquadJS`. Он читает
коллекции `mainstats` и `tempstats` из MongoDB, формирует изображения со
статистикой игроков и обновляет постоянные и недельные таблицы лидеров.

Бот устанавливается на Debian 13 внутри общего проекта и запускается через PM2
от текущего пользователя сервера. Отдельный системный пользователь и
автоматический запуск через systemd не используются.

## Требования

- Debian 13.
- Строго Node.js `18.18.2`.
- npm `9.8.1`.
- PM2.
- Доступ к той же MongoDB, которую использует `rnsStats`.
- Локальный HTTP-прокси `127.0.0.1:1080` для текущей версии кода.
- Доступ к Discord API, Discord Gateway и Steam Web API.

Полная установка Node.js `18.18.2`, PM2 и системных пакетов описана в
[`../README.md`](../README.md).

> **Предупреждение:** Node.js `18.18.2` снята с поддержки. Версия закреплена как
> обязательное требование совместимости этого проекта.

## Системные библиотеки для изображений

Бот использует нативный модуль `canvas`. На Debian установите:

```bash
sudo apt update

sudo apt install -y \
  build-essential \
  python3 \
  pkg-config \
  libcairo2-dev \
  libpango1.0-dev \
  libjpeg-dev \
  libgif-dev \
  librsvg2-dev
```

## Установка зависимостей

Проверьте Node.js:

```bash
node --version
npm --version
```

Ожидается:

```text
v18.18.2
9.8.1
```

Остановите установку при другой версии:

```bash
test "$(node --version)" = "v18.18.2" || {
  echo "Ошибка: требуется строго Node.js v18.18.2"
  exit 1
}
```

Установите зависимости строго из `package-lock.json`:

```bash
cd /home/5thMRsquadJS/discord-bot
npm ci
```

Не используйте каталог `node_modules`, перенесённый с другого компьютера или
другой версии Node.js.

Проверьте модуль `canvas`:

```bash
node -e "import('canvas').then(() => console.log('canvas: готов')).catch(error => { console.error(error); process.exit(1); })"
```

Проверьте синтаксис основного файла:

```bash
node --check index.js
```

## Переменные окружения

Создайте рабочий файл:

```bash
cd /home/5thMRsquadJS/discord-bot
cp .env.example .env
nano .env
chmod 600 .env
```

Переменные:

| Переменная     | Назначение                                            |
| -------------- | ----------------------------------------------------- |
| `CLIENT_TOKEN` | Токен Discord-бота из портала разработчика Discord.   |
| `DBLINK`       | Строка подключения к MongoDB основного сервиса.       |
| `GUILD_ID`     | Идентификатор Discord-сервера для регистрации команд. |
| `STEAM_API`    | Ключ Steam Web API для обработки ссылок и Steam ID.   |

Пример структуры:

```dotenv
CLIENT_TOKEN=вставьте_токен_discord
DBLINK=mongodb://user:password@127.0.0.1:27017/
GUILD_ID=вставьте_id_discord_сервера
STEAM_API=вставьте_ключ_steam_api
```

Бот открывает базу с именем `SquadJS` непосредственно в коде. Значение `DBLINK`
должно вести к MongoDB, в которой основной `rnsStats` создаёт коллекции
`mainstats` и `tempstats`.

Не сохраняйте заполненный `.env` в Git и не публикуйте его содержимое в логах.

## Настройка Discord

Бот должен быть добавлен на сервер Discord с областью `applications.commands` и
правами:

- просмотр каналов;
- отправка сообщений;
- прикрепление файлов;
- чтение истории сообщений;
- использование команд приложений.

В портале разработчика Discord включите необходимые разрешения шлюза для
текущего набора намерений бота.

## Каналы и сообщения таблиц лидеров

Откройте конфигурацию:

```bash
nano /home/5thMRsquadJS/discord-bot/config.js
```

Проверьте следующие значения:

| Параметр                  | Назначение                                   |
| ------------------------- | -------------------------------------------- |
| `statsChannelID`          | Канал, в котором разрешена команда `/stats`. |
| `leaderboadChannelIdMain` | Канал постоянной таблицы лидеров.            |
| `leaderboadChannelIdTemp` | Канал недельной таблицы лидеров.             |
| `top20...MessageID`       | Шесть сообщений постоянной статистики.       |
| `top20...MessageIDTemp`   | Шесть сообщений недельной статистики.        |

Всего бот ожидает 12 существующих сообщений. Он получает их по ID и редактирует
вложения. Автоматического создания этих сообщений пока нет.

Если используется прежнее Discord-приложение и прежний токен, бот сможет
редактировать собственные старые сообщения. Новый Discord-бот не сможет
редактировать сообщения, отправленные другим ботом: потребуется создать новые
сообщения от его имени и заменить все идентификаторы.

## Проверка прокси

В текущем `index.js` закреплён адрес:

```text
http://127.0.0.1:1080
```

Реализация использует HTTP-агенты, поэтому нужен HTTP-прокси с поддержкой
туннеля CONNECT, а не обычный SOCKS-прокси.

Проверьте порт:

```bash
ss -lntp | grep ':1080'
```

Проверьте Discord API через прокси:

```bash
curl --proxy http://127.0.0.1:1080 \
  --connect-timeout 10 \
  https://discord.com/api/v10/gateway
```

При успешном подключении Discord вернёт JSON с адресом шлюза. Если прокси не
работает, бот завершится с ошибкой подключения к `127.0.0.1:1080`.

## Регистрация команд

Команды регистрируются при первой установке и после изменения их структуры:

```bash
cd /home/5thMRsquadJS/discord-bot
npm run commands:deploy
```

Для удаления зарегистрированных команд:

```bash
npm run commands:remove
```

После регистрации проверьте появление `/stats` на Discord-сервере из `GUILD_ID`.

## Запуск через PM2

Запускайте процесс от того же пользователя, который устанавливал проект. Не
используйте `sudo pm2`, если первоначальный запуск выполнялся без `sudo`.

```bash
pm2 start /home/5thMRsquadJS/discord-bot/index.js \
  --name 5thmr-stats-discord \
  --cwd /home/5thMRsquadJS/discord-bot \
  --interpreter /opt/nodejs-18.18.2/bin/node \
  --time \
  --restart-delay 5000
```

Не запускайте несколько экземпляров и не используйте кластерный режим. Иначе
несколько процессов будут одновременно обновлять одни сообщения и записывать
одни временные файлы изображений.

Параметр `--cwd` обязателен: бот загружает изображения и шрифты через пути
`./img/...` и создаёт временные изображения в текущем рабочем каталоге.

Проверьте:

```bash
pm2 status
pm2 describe 5thmr-stats-discord
pm2 logs 5thmr-stats-discord --lines 100
```

В журнале успешного запуска появится сообщение о входе бота в Discord.

## Ручное восстановление после перезагрузки Debian

Автоматический запуск через systemd намеренно не настраивается.

После первоначального запуска обоих сервисов сохраните список PM2:

```bash
pm2 save
```

После перезагрузки сервера восстановите его вручную:

```bash
pm2 resurrect
pm2 status
```

`pm2 save` не включает автоматический запуск. Он только сохраняет список для
последующего ручного восстановления.

## Типовые ошибки

### `ECONNREFUSED 127.0.0.1:1080`

Не запущен обязательный локальный HTTP-прокси.

### Ошибка `canvas`, Cairo или Pango

Установите системные библиотеки из раздела выше, удалите каталог
`discord-bot/node_modules` и повторно выполните `npm ci` на Debian с Node.js
`18.18.2`.

### `Unknown Message`

В `config.js` указан неправильный ID сообщения или сообщение было удалено.

### `Missing Access`

Бот не видит канал, сообщение либо не имеет требуемых прав Discord.

### Команда `/stats` не появилась

Проверьте `CLIENT_TOKEN`, `GUILD_ID`, присутствие бота на сервере и повторно
выполните `npm run commands:deploy`.

### Изображения или шрифты не найдены

Проверьте, что PM2 запустил процесс с рабочим каталогом:

```text
/home/5thMRsquadJS/discord-bot
```

### MongoDB не отвечает

Проверьте `DBLINK`, сетевой доступ, учётные данные и наличие базы `SquadJS` с
коллекциями `mainstats` и `tempstats`.
